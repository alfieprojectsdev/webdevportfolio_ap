Platforms & Production Work

In Production

PipetGo

B2B laboratory marketplace MVP connecting businesses with ISO-accredited testing labs, with multi-tiered pricing and role-based authorization workflows.

Problem: Businesses had no centralized source for accredited labs — data was scattered, outdated, and often missing accreditation details.
Solution: A searchable marketplace with three pricing modes (QUOTE_REQUIRED, FIXED, HYBRID), multi-role authorization, and RFQ workflows connecting certified labs and clients directly.
Stage: MVP in user acceptance testing with initial partner organizations. Tests run against a real Postgres container rather than mocks, with a committed Playwright smoke as the browser-render gate before any PR touching shared UI.
V2 rewrite: V1 shipped and exposed four structural problems that couldn't be fixed incrementally: three incompatible client schemas coexisting, a status transition guard defined but never called, pricing logic buried in a 32-line route-handler conditional, and one order status reachable by two paths with no way to tell them apart. V2 is a ground-up rewrite on vertical slices over a domain kernel under 300 lines, with the boundary enforced by an ESLint rule rather than by discipline.

In Production

ArtPortfolio

Database-driven commission system for a working digital artist, live on its own domain since July 2026. Replaces the earlier static version.

Problem: Commission requests arrived through Discord and Instagram DMs, with no record of what had been asked for, quoted, or accepted.
Solution: Astro SSR with React islands, Postgres on Neon via Drizzle, Cloudinary for image delivery, Resend for mail, Playwright end to end. Requests are written to the database before any email is attempted, so a mail failure cannot lose one. Admin dashboard handles triage, pricing and status.
Impact: In production at dementedb.red, accepting commission requests directly. The database is the source of truth for every request received.

MOVE Faults

GNSS automation monorepo for the PHIVOLCS network, taking raw receiver files through to reviewed station velocities. I'm lead developer on the software stack for MOVE Faults, a nationally funded project led by Dr Bacolcol.

Problem: Network processing ran on decades of fragmented MS-DOS and Bash scripts. Orchestration, fault tolerance and field data capture were all handled by hand.
Solution: Celery and Redis ingestion handling Hatanaka decompression and MD5 deduplication into PostgreSQL with PostGIS and TimescaleDB. A Python wrapper drives Bernese non-interactively from Jinja2 templates. A real-time monitor reads NMEA 0183 over TCP, with a high-pass filter that corrects firmwares reporting velocity in the displacement field. Field crews log site visits in an offline PWA that generates its own UUIDs, so a submission over a bad connection cannot duplicate itself.
Stage: Phased rollout. Geodetic database and documentation portal are done. Field ops, RINEX QC and the IGS downloader are in progress. The Bernese workflow has completed research and is being built.

EIL Hazard Suite

Decoupled geohazard system: a headless Python engine that certifies land parcels against earthquake-induced landslide hazard, paired with a React app for reviewing the analysis behind each verdict.

Problem: Certifying a land parcel against earthquake-induced landslide hazard required manual GIS desktop work, with no programmatic access and no way for an assessor to check the reasoning behind a result.
Solution: EIL-Calc takes a parcel polygon, resolves the best available elevation data (5 m IfSAR, 30 m SRTM as fallback) and runs two independent checks: how much ground inside the parcel sits above 16 degrees, and whether debris from the highest peak within about a kilometre could travel far enough to reach it. EIL-Viz renders the slope grid and the steepest-descent runout paths so an assessor can review the reasoning rather than just the verdict.
Stage: EIL-Calc agrees with assessor ground truth on about 90% of 50 test parcels. An earlier version returned CERTIFIED SAFE when the analysis failed outright; it refuses to answer now.

About Me

I work at PHIVOLCS processing GNSS and geophysical data for earthquake research and fault monitoring, and I write the software that replaces the manual parts. I have been there since 2009.

Alongside that I do contract platform engineering: CI/CD, cloud deployment, and release gating for production systems. I’ve gotten suspicious of architectures I can’t still understand six months later.

In practice that means I write the test first when a bug is subtle, and skip it entirely when I’m still sketching. I keep READMEs a stranger could follow, on the theory that in six months I am the stranger. And I ship the boring version before finding out whether anyone wanted the interesting one.

Outside work I’m usually helping my kids with homework, or automating something that didn’t need automating.
